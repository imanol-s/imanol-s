## My contribution

I was lead developer on this Fall 2024 class project: a Java implementation of PERT/CPM scheduling that models task dependencies as a directed acyclic graph.

## The problem

Scheduling by hand becomes error-prone as dependencies grow. One incorrect completion time can change the slack calculation and misidentify the critical path.

## The implementation

The graph uses adjacency lists. A DFS-based topological sort tracks active nodes to detect cycles before scheduling begins. Invalid cyclic input stops the calculation.

A forward pass computes earliest start and finish times. A backward pass computes latest start and finish times. Together, the passes identify slack and the zero-slack tasks that determine the project duration, in O(V+E) time.

The output includes each task's earliest completion, latest completion, slack, and critical status.

## How I checked it

I used course-provided inputs and generated task networks with known critical paths to check the calculations across different graph sizes and dependency structures.

## What this work shows

Turning graph theory into a practical tool, choosing a representation with clear complexity, and validating assumptions before computing results.
